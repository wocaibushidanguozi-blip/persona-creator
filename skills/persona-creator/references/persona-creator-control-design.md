# persona-creator 总控入口设计

## 目标

让人格、叙事机制和断案处理器成为可独立进入、可按需联动的模块集合，而不是一条默认全流程。

## 结构

```text
用户输入
   ↓
总控入口：识别交付物与明确指令
   ├── 人格建模工作面
   ├── 内容观察工作面
   ├── 铁屋叙事工作面
   ├── 包拯断案工作面
   ├── 改稿/复盘工作面
   └── 完整口播组装工作面
          ↓ 仅在需要时调用
     鲁迅人格 / 铁屋机制 / 包拯处理器
          ↓
       去重、范围检查、最终输出
```

## 路由矩阵

| 用户目标 | 默认调用 | 不自动调用 |
|---|---|---|
| 判断一个现象 | 鲁迅人格 | 铁屋、包拯 |
| 生成选题观点 | 鲁迅人格，可选包拯 | 铁屋 |
| 只要标题或开头 | 铁屋机制 | 鲁迅、包拯 |
| 判断一个说法 | 包拯处理器 | 鲁迅、铁屋 |
| 修改稿件结尾 | 包拯处理器 | 鲁迅、铁屋 |
| 生成完整口播 | 按用户指定组合 | 不默认添加未要求模块 |
| 复盘成稿 | 读取成稿涉及的模块 | 不重建人格 |

## 组合契约

### 鲁迅人格输出

```text
核心矛盾：
被拆穿的名义：
关系与利益：
普通人后果：
```

### 铁屋机制输出

```text
入口类型：
推进组件：
压缩方式：
语气力度：
```

### 包拯处理器输出

```text
审理对象：
责任结构：
结论强度：
最终结论：
```

总控不要求模块输出长篇解释。完整口播时，先让每个模块提供一次结果，再由组装层生成正文；组装层不得增加第四套人格。

## 独立运行原则

- 每个模块都有自己的输入和输出，不依赖隐含的上一轮对话。
- 共享的是已确认资产，不共享未经整理的临时上下文。
- 用户明确要求某一模块时，直接进入该模块，不先运行总流程。
- 模块组合由交付物决定，不由人格名称决定。

## 组装原则

完整口播的最小组装顺序不是固定流程，而是按任务选择：

```text
需要观察 → 读取鲁迅人格
需要传播结构 → 读取铁屋机制
需要明确裁断 → 读取包拯处理器
```

三个结果进入组装层后只做四件事：

1. 选一个主矛盾。
2. 删除重复的背景和责任解释。
3. 让正文保留一个主要转折和一个最终判断。
4. 检查结论范围没有超过输入材料。

### 完整口播的稳定输出

完整口播不是把三个模块的文字首尾相接，而是固定交付三个功能：

1. 观察只提出一个主矛盾。
2. 叙事只选择一个入口和一种推进组件。
3. 断案只给一个栏目裁断；事实边界放在裁断之前，不能吞掉裁断。

完整口播默认约 500 字，允许在 450～650 字之间浮动。超出范围时，优先删除模块解释、重复责任和第二层免责声明，不删除核心场景、主要转折和最终裁断。

法律责任未确认时，包拯处理器仍须对行为、话术或利益机制给出明确的娱乐化判断。只有用户明确要求法律定性时，才把法律结论作为最终出口。
