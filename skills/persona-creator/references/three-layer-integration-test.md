# 三层资产联动对照测试

日期：2026-08-14

状态：第一轮三层联动测试

## 测试设置

统一题目：网红探店把广告说成体验。

统一边界：不讨论具体账号、商家或真实事件，只测试一般机制，不生成事实指控。

对照组：

1. 鲁迅人格 + 铁屋叙事机制
2. 铁屋叙事机制 + 包拯断案处理器
3. 鲁迅人格 + 铁屋叙事机制 + 包拯断案处理器

## 一、鲁迅人格 + 铁屋机制

### 分工

- 鲁迅人格：观察“分享体验”与“商业传播”之间的身份差距，拆分创作者、商家、平台和观众的责任。
- 铁屋机制：使用认知错位、身份反转和短句压缩。
- 不调用包拯处理器：结尾明确，但不采用断案格式。

### 输出

#### 标题

把广告说成体验，观众就得替它承担判断的代价

#### 口播稿

探店视频最容易让人相信的地方，是它看起来不像广告。

有人替你走进店里，替你点菜，替你说一句“这家值得”。你看到的不是一张广告单，而是一个好像和你一样的消费者。

可如果这份推荐背后存在商业关系，身份就发生了变化：他不只是吃饭的人，也是传播信息的人。观众以为自己得到了一次体验，实际可能接收的是一段没有说清身份的推广。

这不意味着所有探店都是假的。问题是，广告可以有收益，体验不能没有身份。把广告说成体验，最后被消费的就不只是那家店，还有观众本来应该拥有的判断。

### 结果

- 有鲁迅人格的名义拆解、关系观察和后果追问。
- 有铁屋机制的入口、身份反转和记忆句。
- 结尾已经明确，但没有“审理对象—责任—结论”的显式断案结构。

判断：通过。适合一般评论和观点型口播。

## 二、铁屋机制 + 包拯处理器

### 分工

- 铁屋机制：提供标题、入口、认知错位和短句压缩。
- 包拯处理器：直接确定审理对象、责任关系和结论。
- 不调用鲁迅人格：不额外加入复杂的社会观察或鲁迅式价值张力。

### 输出

#### 标题

探店可以做广告，但不能让观众替隐藏的身份买单

#### 口播稿

今天审理的不是探店，也不是广告，而是把广告说成普通体验的做法。

创作者可以获得收益，商家可以进行宣传，平台也可以提供传播渠道，这些本身都不构成问题。

问题在于，创作者如果不说明商业关系，却继续使用“我替你试过了”的消费者身份，观众就失去了判断这段推荐的必要信息。

本案责任分开来看：创作者对身份隐藏承担直接责任，商家对宣传安排承担组织和受益责任，平台对信息透明承担条件责任。观众需要保持判断，但不能替隐藏身份造成的误导承担全部代价。

结论是：广告本身可以成立，身份不透明的广告表达失当；目前只能判断这种传播方式有问题，不能据此判定所有探店内容或相关人员都在欺骗。

### 结果

- 有铁屋机制的入口和短句压缩。
- 包拯处理器清楚呈现审理对象、责任类别、结论范围。
- 没有鲁迅人格的复杂观察，稿件更像结构清楚的判断稿，情绪和文学余味较少。

判断：通过。适合用户明确要求“断案”或“给结论”的任务。

## 三、鲁迅人格 + 铁屋机制 + 包拯处理器

### 分工

- 鲁迅人格先发现“普通体验”名义背后的身份和利益关系。
- 铁屋机制把这个差距组织成认知错位、身份反转和可记忆句。
- 包拯处理器最后限定审理对象、拆分责任并下结论。

### 输出

#### 标题

最像普通人的广告，往往最不肯承认自己是广告

#### 口播稿

探店视频最方便的地方，是广告拿走了，普通人的外表留下了。

有人替你进店、点菜、评价，好像只是把自己的午饭告诉你。可一旦这份推荐背后存在商业关系，他就不只是吃饭的人，也是传播信息的人。

这时，观众看到的已经不只是一顿饭，而是一种身份错位：广告借用了体验的外表，推广借用了普通人的信任。

但这件事不能简单说成“网红都是骗子”。创作者可以做广告，商家可以做宣传，平台可以提供流量，观众也需要保留判断。问题在于，谁拿到了收益，谁就应该把身份说清楚；谁掌握了传播和规则，谁就不能把全部判断成本留给付款的人。

所以本案审理的不是广告本身，而是隐藏商业关系、借普通体验取得信任的表达方式。结论很明确：广告可以有收益，体验不能没有身份；身份没有说清楚，传播就已经失当。

### 结果

- 鲁迅人格提供了“广告借体验外表取得信任”的观察角度。
- 铁屋机制提供了标题、认知错位、身份反转和压缩句。
- 包拯处理器提供了“审理的不是广告本身”这一对象限定、责任拆分和最终定性。
- 三层没有互相替代：观察、叙事、判定分别可见。

判断：通过，但稿件比前两组更长，必须在真实写稿中控制每层的重复解释。

## 四、对照结论

| 测试组合 | 主要优势 | 主要缺口 |
|---|---|---|
| 鲁迅 + 铁屋 | 观察有余味，传播性强 | 责任和结论可能不够显式 |
| 铁屋 + 包拯 | 结构清楚，结论稳定 | 观察深度和情绪余波较弱 |
| 三层联动 | 观察、节奏、责任和结论最完整 | 容易重复，稿件变长 |

## 五、联动规则候选

### 默认调用

完整口播任务可以调用三层，但每层只输出一次自己的结果：

```text
鲁迅人格：只给核心观察和判断
铁屋机制：只决定开头、推进、压缩和节奏
包拯处理器：只确定审理对象、责任和最终结论
```

### 独立调用

- 用户要选题或观点：优先鲁迅人格，可不调用其他模块。
- 用户要标题、开头或节奏：优先铁屋机制，可不调用其他模块。
- 用户要断案、结论或修改结尾：优先包拯处理器，可不调用其他模块。
- 用户要完整口播：才组合三层。

### 防重复规则

- 鲁迅人格不要再次解释铁屋机制已经完成的反转。
- 铁屋机制不要替包拯处理器重复列责任。
- 包拯处理器不要重新讲完整背景，只收束已有判断。
- 三层联动时，正文只保留一个主矛盾、一个主要责任判断和一个最终结论。

## 六、最终判断

三组测试均通过，三层资产具备联动能力。当前最大风险不是记忆错乱，而是信息重复和稿件变长。下一步可以冻结三层模块，开始设计 persona-creator 的总控入口和按需调用规则。
