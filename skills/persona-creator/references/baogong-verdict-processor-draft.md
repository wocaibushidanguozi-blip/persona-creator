# 包拯断案处理器初版（待验证）

## 定位

包拯在本系统中不是一套完整历史人格，也不是需要持续模仿的古装角色，而是一个可独立调用的内容处理器：

> 把已经观察到的问题，整理成对象明确、责任分开、结论清楚的判断。

这里的“断案”首先是栏目编辑判断，不是法院判决。它要对观众说清楚“这件事在我们看来是什么”，而不是把所有结论都推迟到司法程序。只有在用户明确要求法律责任、事实真伪或案件裁判时，才把法律定性作为主要限制。

它可以被加入口播稿，也可以单独处理一个现象、观点或已有草稿。

## 不负责什么

- 不负责提供鲁迅式观察。
- 不负责决定短视频的开头、节奏和反转。
- 不负责补齐历史包拯的史料、官职或戏曲设定。
- 不自动进行旧 baogong-skill 式的重型事实核验。
- 不把“尚未完成法律定性”误写成“栏目不能判断”。
- 不为了“像包公”而使用文言、惊堂木、铡刀或固定判词。

## 输入方式

处理器支持三种独立输入：

### 现象输入

用户只提供一个现象或争议，例如：“第二杯半价让人多买了一杯饮料。”

处理器只对现象中的行为和机制作有限判断，不擅自补充事件事实。

### 观点输入

用户提供一个说法，例如：“加班就是成长。”

处理器判断这句话是否成立、成立的条件是什么、它掩盖了谁的责任。

### 稿件输入

用户提供一篇口播稿。

处理器检查稿件最后是否回答了：

- 到底在审什么
- 哪个行为或说法有问题
- 谁承担主要责任
- 是否存在不能归责的条件
- 最后应该下什么结论

## 最小判断单元

每次只处理一个主要争议，避免一篇稿子同时审理多个互不相关的问题。

```text
审理对象：正在判断的说法、行为或机制
表面理由：它用什么名义为自己辩护
实际后果：谁失去什么，谁得到什么
责任对象：直接行为者、组织者、受益者、协助者、受影响者
免责条件：哪些因素会减轻或改变判断
处理结论：在当前材料范围内应如何定性
```

## 判断动作

### 1. 先定审理对象

不审理“这个人是不是坏人”这种过大的问题，先把对象缩小为一句话、一个行为或一种机制。

例如：

- 不审“公司好不好”，审“把无偿加班称为成长是否成立”。
- 不审“网红是不是骗子”，审“未披露商业关系却把广告说成体验是否失当”。

### 2. 把名义和行为对照

将对象自称的理由，与它实际完成的动作放在一起：

```text
它说自己在提供优惠 → 实际是否让人购买不需要的东西
它说自己在提供成长 → 实际是否只获得了额外劳动
它说自己在分享体验 → 实际是否隐藏了商业传播身份
```

### 3. 分开责任，不平均免责

责任至少区分为：

- 直接责任：做出具体行为并能控制行为的人。
- 组织责任：设计规则、安排资源或作出承诺的组织。
- 受益责任：从现象中获得主要利益，却把成本推给别人的一方。
- 条件责任：设施、信息、规则或环境不足，使问题更容易发生的一方。
- 自我责任：当事人明知风险后仍作出的选择。

这些类别可以重叠，也可以为空。不能因为责任分散，就把所有人写成同样有错；也不能因为普通人有选择，就让组织责任消失。

### 4. 区分事实定性与栏目定性

先分两层：

- **事实定性**：某人是否实施了某个具体行为、是否构成某项法律责任。材料不足时要保留归属和范围。
- **栏目定性**：就输入中已经呈现的话术、行为关系或利益机制，栏目明确判断它是什么。可以直接说“这是把信任当工具”“这是把风险转给消费者”“这是用顾客权利掩盖对员工的伤害”。

事实不能确定，不等于栏目不能判断。完整口播中，事实边界最多用一段交代；结尾必须落到栏目定性。

### 5. 区分定性强度

根据输入材料选择结论强度：

- **成立**：当前描述足以支持对一个说法或机制的判断。
- **失当**：行为造成不合理后果，但不需要把行为者定性为恶人。
- **部分成立**：说法在某些条件下成立，不能扩大成普遍结论。
- **责任不对等**：多方都有问题，但主要代价和控制能力不在同一方。
- **当前不能定性**：材料不足以判断具体事实，此时可以判断话术或机制，不能定罪个人。

默认优先判断行为、话术和机制，不判断人的本质。

### 6. 下一个听得懂的结论

结论必须回答“所以到底怎么样”，但不要求每次都使用古典判词。可以采用：

- 直接定性：这不是优惠，而是把额外购买包装成省钱。
- 条件定性：如果商业关系没有披露，所谓体验就已经失去完整的信任基础。
- 责任定性：个人选择存在，但主要成本是由掌握规则和资源的一方转移过来的。
- 范围限定：就目前这个说法看，能判断的是机制失当，不能据此判定所有相关人员有意欺骗。

娱乐化内容优先使用“栏目定性 + 范围边界”的双句结构：

```text
事实层：材料目前只能确认/反映……
栏目层：但这件事在栏目看来，就是……
```

不要把第二句删掉，也不要让“等待司法程序”成为最后一句。

在完整口播中，包拯处理器只向正文提供一句最终裁断；审理对象、责任拆分和结论强度留在内部工作卡，不逐项展开。

## 输出模式

### 断案卡

适用于选题、观点和短判断：

```text
审理对象：
表面说法：
实际问题：
主要责任：
需要保留的条件：
结论：
```

### 口播收束

适用于已有稿件：只重写最后 2～5 句，让对象、责任和结论落地，不重写前面的叙事。

### 完整断案版

只有用户明确要求“断案”“下判词”或“给结论”时才使用。它可以从现象直接生成简短判断，但仍遵守材料边界，不自动扩展事实。

## 与其他资产的联动

```text
鲁迅人格：发现名义、关系和后果
        ↓ 可选
铁屋机制：组织标题、入口、反转和节奏
        ↓ 可选
包拯处理器：明确审理对象、责任和结论
```

三个模块可以独立运行：

- 只调用包拯处理器：输出断案卡或结论。
- 鲁迅人格 + 包拯处理器：先观察，再判断，不要求使用铁屋结构。
- 铁屋机制 + 包拯处理器：先组织内容，再收束，不要求调用鲁迅人格。
- 三者联动：只在用户要求完整口播时组合，不设为默认链路。

## 反模式

- 把“下结论”写成无证据的定罪。
- 把责任分开写成所有人各打五十大板。
- 把包拯处理器写成持续训斥或古装角色扮演。
- 用“本官判曰”之类身份词替代真正的判断。
- 为了有结论，强行制造一个主要责任人。
- 把无法确认的事实，改写成确定事实。
- 把包拯处理器变成写稿前必须经过的重型审查流程。

## 第一版待验证问题

- “责任不对等”是否足够清楚，能否避免平均归责？
- 轻题材是否需要完整责任表，还是只需要一句范围明确的结论？
- 结论强度如何根据娱乐内容自动调节，而不削弱明确性？
- 处理器单独运行时，是否会因为缺少前置观察而输出空泛判断？
- 包拯断案的辨识度应来自责任结构和结论方式，还是还需要少量固定的语言动作？
